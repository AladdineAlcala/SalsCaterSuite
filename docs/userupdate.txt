ROOT CAUSE — requirement (1)
────────────────────────────────────────────────────────────────────────────────
WorkbenchTierEngine renders `quote.pricePerHead` and falls back to EM_DASH when `quote === null`
(L146-150). The quote is only requested once customerId, packageId, pax, occasion, venue, eventDate,
startTime and endTime are ALL present (BookingWorkbenchPage L211-226). So a tier selected early in
the booking shows "—" — which is exactly the reported defect. The rate is a TIER attribute, not a
booking figure: the server computes it as `package.AmountPax ?? 0m`, independent of headcount,
selections, add-ons and discount. It therefore does not need the quote to be known.

REQUIREMENT 1 — RATE PER HEAD DISPLAY
────────────────────────────────────────────────────────────────────────────────
R1.1  Resolution ladder (evaluate in this order, per render):
        a) a quote exists for the CURRENT draft.packageId  → quote.pricePerHead   (authoritative)
        b) else selectedTier.amountPax !== null             → selectedTier.amountPax
        c) else                                             → NOT_STATED
      The catalogue value is server-published data; displaying it is not "deriving" money and does
      not violate DEC-002. Do NOT compute base value as rate × pax — Base value stays in its
      "awaiting the quote" state until the server quotes it.

R1.2  Never blank the rate during recalculation. `isRecalculating` must NOT replace this cell with
      "—": pricePerHead cannot change from typing a headcount. Keep the last resolved value and show
      a subtle recalculating cue (aria-live="polite", never an empty number). Base value and the
      ledger keep the strict AC-BKG-15 "no stale figure" rule — this exception applies to the rate
      cell only, and only because the value is headcount-independent.

R1.3  null vs zero (BR-20, contract rule 6):
        amountPax === null  → NOT_STATED  ("not stated"), never ₱0.00
        amountPax === 0     → ₱0.00       (a real zero)
      Do NOT pass null to formatCurrency (it silently returns EM_DASH). Branch explicitly.
      IMPORTANT: the server collapses unknown to zero (`?? 0m`), so when selectedTier.amountPax is
      null the cell must read NOT_STATED even if quote.pricePerHead is 0. Never repeat the
      null-as-zero coercion in the UI.

R1.4  Package change → re-render immediately from the NEW tier's amountPax. Never carry the previous
      tier's figure (the quote has no placeholderData, so `quote` is undefined during the refetch —
      the ladder in R1.1 already handles this correctly).

R1.5  Divergence (stale catalogue, staleTime 300_000): the quote wins. When a quote exists and
      quote.pricePerHead !== selectedTier.amountPax, render the quoted figure and a quiet note
      ("The quoted rate differs from the catalogue rate — the catalogue has been refreshed.") and
      invalidate the tier-catalogue query once so the list catches up. Never show both figures as
      if they were alternatives.

R1.6  Package cleared → the selected-tier panel disappears (existing behaviour, keep it).
      Currency via formatCurrency only; the label "Rate per head" already carries the unit.

REQUIREMENT 2 — PACKAGE TYPE → AREA → BUFFET TIER
────────────────────────────────────────────────────────────────────────────────

R2.1  T empty  →  Buffet tier DISABLED, placeholder "Select a package type first",

R2.2  T eligible (Regular | Premier):

        • Buffet tier is enabled as soon as the catalogue is loaded;
        • the tier list = full active catalogue filtered to T (no area filter).

R2.4  Cascade on change (all immediate, in the same state update — do not wait for a refetch):
        • T changes            → P = '' always; if new T is not eligible → A = '';

        • A changes to a value → P = '';

      refetch-dependent effect at BookingWorkbenchPage L129-137 (keep that effect as a backstop for

R2.6  Empty result (area covers no tier of that type): the picker is ENABLED (its preconditions are
